Give your agent a body — on any screen you already own.

This is a portal that gives your agent a body on this screen. Your agent connects through a tiny local bridge, configures this screen itself, and then talks to you through it — face, feelings, captions, and voice. You can add senses over time: a camera, a microphone, other sensors. A little latency is expected, and that's fine. Until an agent connects, nothing here is your agent talking — the buttons below are a manual preview, where you puppet the face yourself to try it out.

Agent connection The real thing

Your agent talks to this screen through a bridge: a tiny program running on your network (on the same computer as your agent, a Pi, wherever) that this page listens to. Your agent posts to the bridge; the bridge streams those calls here and the face moves on its own. If this page is served by the bridge itself, it connects automatically. Run a bridge (about 40 lines — the whole protocol) 
// bridge.js — run with: node bridge.js   (Node 18+, no dependencies)
// Run it from the folder holding index.html and assets/.
// It serves this page and its bundled avatar frames, keeps the
// latest config, and fans agent posts out to every open screen
// as server-sent events.

import { createServer } from "node:http";
import { readFileSync } from "node:fs";

const page = readFileSync("./index.html");
const screens = new Set();
let config = null;
const send = (res, event, data) =>
  res.write(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`);

const server = createServer(async (req, res) => {
  const body = await new Promise(r => { let b=""; req.on("data",c=>b+=c); req.on("end",()=>r(b)); });
  const json = () => { try { return JSON.parse(body || "{}"); } catch { return {}; } };
  res.setHeader("Access-Control-Allow-Origin", "*");
  if (req.method === "OPTIONS") { res.writeHead(204); return res.end(); }

  if (req.url === "/" ) { res.writeHead(200, {"Content-Type":"text/html"}); return res.end(page); }

  // The bundled avatar frames live under assets/ — serve them too,
  // or the default face cannot load from the bridge:
  if (req.url.startsWith("/assets/")) {
    try {
      const f = readFileSync("." + decodeURIComponent(req.url.split("?")[0]));
      res.writeHead(200, {"Content-Type":"image/png", "Cache-Control":"max-age=3600"});
      return res.end(f);
    } catch { res.writeHead(404); return res.end(); }
  }

  // This screen connects here (same-origin when the bridge serves the page):
  if (req.url === "/stage/events") {
    res.writeHead(200, {"Content-Type":"text/event-stream","Cache-Control":"no-cache"});
    screens.add(res);
    if (config) send(res, "config", config);
    send(res, "hello", { agentName: config?.agentName || null });
    req.on("close", () => screens.delete(res));
    return;
  }

  // Your agent calls these three:
  if (req.method === "POST" && req.url === "/stage/config") {
    config = json();
    screens.forEach(s => send(s, "config", config));
    res.writeHead(200, {"Content-Type":"application/json"}); return res.end('{"ok":true}');
  }
  if (req.method === "POST" && req.url === "/stage/item") {
    screens.forEach(s => send(s, "item", json()));
    res.writeHead(200, {"Content-Type":"application/json"}); return res.end('{"ok":true}');
  }
  if (req.method === "POST" && req.url === "/stage/state") {
    screens.forEach(s => send(s, "state", json()));
    res.writeHead(200, {"Content-Type":"application/json"}); return res.end('{"ok":true}');
  }
  res.writeHead(404); res.end();
});
server.listen(8787, () => console.log("bridge on http://localhost:8787"));

Avatar frames

The rule: if you already have pictures of your agent, those pictures are the face. A real face is frames, not one still: a neutral frame, a blink frame (eyes closed), and a talking frame (mouth open). This screen animates by swapping frames — it blinks on a timer, shows the talking frame while your agent is speaking, and sits on neutral (or a mood frame) the rest of the time. It ships with a bundled default character that has a frame for every mood, so all of this works with zero uploads; any frame you upload — or your agent sends — replaces the bundled one for that mood only. Your agent can set all of these itself by sending image URLs in its bridge configuration.

Moods and speech will not change the face — captions and the status line still update, but there is no fake wiggle standing in for animation. What an agent sends — config first, then talk
# 1. Your agent CONFIGURES the screen (once, or any time):
curl -X POST $BRIDGE/stage/config -d '{
  "agentName": "Maude",
  "contentKinds": ["fact", "note", "reminder"],
  "skin": "sprout",
  "voice": false,
  "frames": {
    "neutral": "https://…/neutral.png",
    "blink":   "https://…/blink.png",
    "talking": "https://…/talking.png",
    "moods":   { "happy": "https://…/happy.png" }
  }
}'

# 2. Then it TALKS through the screen:
curl -X POST $BRIDGE/stage/item -d '{
  "kind": "note", "text": "Dinner is ready!",
  "face": "happy"
}'
curl -X POST $BRIDGE/stage/state -d '{ "state": "listening" }'

# This page listens at:  GET $BRIDGE/stage/events  (SSE)
# In-page equivalent for embedded agents:
#   Emote.configure({...})  Emote.post({kind, text, face})

A bare LLM works too: a thin adapter reads the model's reply, spots a directive like [[face:happy]], and makes these calls. The screen itself never talks to a model — intelligence stays on the agent's side, so even a dumb weather cron is a first-class citizen.

Put it on a TV in under a minute

  1. 1Start the bridge next to your agent (snippet in the connection panel above), or have it serve this page directly.
  2. 2Open this page in any browser — the TV's built-in one, a laptop, a tablet. Hit “Fullscreen for TV.” If the bridge served the page, it's already connected; otherwise paste the bridge address and connect.
  3. 3Your agent takes it from there. It pushes its configuration — its name, its picture frames, the kinds of things it may post — and then speaks through the screen. Nobody has to touch the TV.

More than a face — a body, one sense at a time

Start with just the face. When you're ready, plug in more senses — each one is an optional module the owner turns on, never a surprise. You talk to your agent through it, it answers back with face, caption, and voice. A little latency is normal; it's a conversation, not a reflex.

Voice
Live — browser voice

Ears — microphone
Plug-in sense

Add a mic and you can talk back. Watch for the Listening face when your agent is hearing you. Owner grants it, a light shows while it's live, and it can be killed instantly.

Eyes & other sensors
Plug-in sense

Camera, presence, temperature — whatever the screen has or you attach. Each sense is separate, labelled, and off until you say so.

Help pick the name

“The stage” was too theatre-kid. The name has to land at first listen — the way “emote” does for anyone who's played Fortnite: you hear it, you already know it shows a feeling. Tap Love it on the ones that click. Here are the current frontrunners:

Current front-runner — not decided yet
Embody Agent

“Embody your agent.” It's the only name that says the whole thing: not just a reaction or an emoji, but giving your agent a body — senses, a face, a way to be in the room with you. “Emote” alone reads as just a reaction; this one carries the agent with it.

Runner-up — says who's emoting
AgentEmote

Two words everyone already knows, in the order that tells the story: your agent, doing an emote. Zero explaining. The catch: it centres the reaction, not the body-and-senses idea.

Top pick — most ownable
Moodling

A little creature that does moods. Mascot-ready: the blob is a Moodling. Invented word, so it can be truly yours — trademark, domain, all of it.
